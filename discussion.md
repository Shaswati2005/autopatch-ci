## Project Idea: AutoP: Cl (Aut CI/CD Healing Agent)

Track: Taskmaster (or Fortified Enterprise Fleet)

and Concept: An autonomous DevOps agent that intercept failed CI/CD pipeline runs (GitHub Actions, Cloud Build), analyzes build logs recent git commits, replicates the error in a container, a minimal diff/fix using Gemini, runs tests to verify the fix, and automatically creates a PR with the fix and resolution breakdown.

## 1. Why This Has a High Chance of Winning

- \+ Solves a Real, Ubiquitous Developer Problem: Developers spend hours sifting through thousands of lines of verbose build logs to fix small typos, missing dependencies, or breaking API changes.

- \+ Proves "Real Autonomous Execution": Instead of waiting for a user prompt, it acts asynchronously on events (a webhook from a failed CI run triggers the agent in the background).

- \+ Clear Cloud & Tech Stack Showcase: Fits cleanly into Google Cloud services (Cloud Run, Cloud Pub/Sub, Vertex Al / Gemini API) and Google's Agent Development Kit (ADK).

## 2. Core Workflow & Agent Architecture

```
[ GitHub Actions / Cloud Build Failure ]
v (Webhook Event)
[ Cloud Pub/Sub ]
v
[ Cloud Run: ADK Agent ]
1. Diagnostic Agent (Parses logs, fetches git diff)
2. Code Patch Agent (Gemini 3.5 Flash generates fix)

v

```

- . Trigger (Asynchronous Intake): A GitHub Action or Cloud Build job fails and fires a webhook payload to Cloud Pub/Sub containing build log URLs, commit SHA, and branch info.

- IN) . Step 1 — Diagnostics (Tool Call): ADK agent fetches the raw build logs via GitHub API, parses out the exact error snippet (e.g., TypeScript Compilation Export, Dependency Mismatch), and fetches recent commit diffs.

- 3. Step 2 — Root Cause Analysis & Patching: Gemini 3.5 Flash analyzes the code context around the failure and produces a minimal code modification patch.

- 4. Step 3 — Local Verification Loop: The agent uses a tool to trigger a lightweight test execution in Google Cloud Build to verify that the generated patch actually resolves the build error without introducing new test failures.

- a . Step 4 — Automated Delivery: The agent creates a new Git branch (autopatch/fix-build-1234), commits the fix, opens a Pull Request on GitHub, and posts a detailed summary explaining Why the build failed and How the patch fixes it.

## Tool Definitions inside Google ADK:

You will define 4 custom Python tool functions registered with your ADK agent:

- 1. fetch_build_logs(run_id, repo)

- o API Call: Calls GitHub REST API GET /repos/{owner}/{repo}/actions/runs/{run_id}/logs or parses log contents passed from Cloud Build.

- o Returns: Raw error stack trace (e.g., SyntaxError, TypeScript error TS2322, failing PyTest output).

- 2. commit_sha, error_file_path)

- o API Call: Calls GitHub REST API GET /repos/{owner}/{repo}/contents/{path}?ref={commit_sha}.

- o Returns: Code context surrounding the failing line.

- 3. verify_patch_cloud_build(repo, patch_diff)

- o API Call: Triggers a ephemeral Google Cloud Build run with the patched code applied in an isolated docker container.

## 2. The End-to-End Architecture

The system operates across four distinct layers. Your teammate should build these in order:

## « Layer 1: Ingestion & Security:

- o Build a FastAPI endpoint on Google Cloud Run to receive JSON payloads from GitHub webhooks (either via a GitHub App or a custom GitHub Action wrapper).

- o Route the raw build logs through Google Cloud Model Armor and Cloud SDP to strip malicious prompt injections and redact secrets.

- o Push the sanitized payload to a Google Cloud Pub/Sub topic called ci-failure-events.

## « Layer 2: Multi-Agent Reasoning Engine:

- o Use Gemma for an initial triage to quickly categorize the error; if it is a third-party outage (like NPM being down), halt the process and create an Incident Report Issue.

- o Ifitis a code bug, use the ADK agent to fetch the error snippet, and have Gemini 3.5 Flash generate a minimal Git diff to fix it.

- o Have Gemini generate a new unit test file to catch the original failure edge case to prevent regressions.

## \+ Layer 3: Isolated Verification (The Sandbox):

- o The agent spins up a short-lived Docker container in Google Cloud Build to apply the Gemini patch and run the test suite.

- o If the patch fails, feed the error back to Gemini for refinement, hard-capping the loop at a maximum of 3 attempts to prevent infinite billing spikes.

## \+ Layer 4: Cross-Branch Governance & Ul:

- o Simulate merging the patch into downstream branches (like main) via Cloud Build to ensure it doesn't cause broader regressions.

- o The agent must never auto-merge code; it should output a Draft Pull Request containing the fix, the tests, and an interactive Markdown summary.

- o Allow developers to reply to the PR with commands (e.g., @autopatch-bot sync --target main), which the ADK agent catches to regenerate the patch context.
